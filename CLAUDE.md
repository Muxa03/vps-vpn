## 1. Контекст проекта

- Строим собственный VPN-сервис для пользователей из России.
- Основная связка: **VLESS + RAW(TCP) + REALITY** (Xray). На домашнем Wi-Fi работает, на мобильном интернете (LTE) бывают заминки, а у части операторов не работают релеи.
- Инфраструктура: несколько зарубежных VPS (в основном Германия и Нидерланды) и один VPS в России (используется как релей/каскад).

> **Заполни при первом запуске** (спроси у владельца и допиши сюда, без паролей и ключей):
> - список серверов: роль (entry / exit / relay), страна, хостер, **ASN**, IP-подсеть /24;
> - панель (3x-ui / Remnawave / Marzban / голый Xray) и версия ядра Xray на серверах;
> - клиентские приложения пользователей (v2rayNG, Happ, Streisand, v2RayTun, Hiddify, Karing…);
> - на каких операторах и в каких регионах проблемы (МТС / МегаФон / Билайн / T2 / Yota, регион).

## 2. Главное, что нужно знать про LTE в РФ (состояние на сентябрь 2026)

На мобильных сетях ТСПУ одновременно применяет несколько разных механизмов. Сначала определи, какой из них сработал, и только потом что-то меняй.

1. **«TCP 16-20» / «L4-25»**: соединение к IP «подозрительных» зарубежных хостингов замерзает примерно после 15–20 КБ, точнее после ~25 пакетов в обе стороны. Режет и TCP, и UDP. **Настройками Xray не лечится**, помогают только смена IP/хостера или релей. Под раздачу попадают Hetzner, OVH, DigitalOcean, Contabo, Scaleway, Vultr, Akamai/Linode, Oracle, AWS, Google Cloud, Azure, Gcore, BuyVM, Melbicom, CDN77, Cloudflare.
2. **«Июньская схема 2026»**: заморозка на ~120 с, если одновременно выполнены три условия: IP сервера в «подозрительной подсети» (включая **Selectel, Yandex Cloud, Cloud.ru**), TLS-отпечаток **chrome / safari / ios** и больше 3 почти одновременных TLS-хендшейков за ~60 с. Если сменить отпечаток уже во время заморозки, блок растягивается на ~600 с на все TLS. **Скорее всего, именно это ломает ваш RU-релей**: VLESS+RAW+Vision открывает отдельный TLS на каждое соединение, а по умолчанию стоит fingerprint `chrome`.
3. **Белые списки** (регионами, по операторам): пропускается только трафик к разрешённым IP, а всё чаще к **IP + SNI** одновременно. UDP режется почти целиком. Обходится только релеем с IP из белого списка (фактически Yandex Cloud или VK Cloud) и SNI из белого списка.
4. **Блоки IP и подсетей** (например, волна 04.08.2026 по подсетям крупных хостеров) и **динамические триггерные блоки** на ~10 минут для одного абонента.
5. **Детект VPN российскими приложениями** (с 15.04.2026): они видят IP выхода и открытые локальные прокси-порты. Поэтому российский трафик должен идти мимо VPN, а IP выхода должен отличаться от IP входа.

## 3. Правила работы (обязательные)

- **Не используй `fingerprint: "chrome"` (а также `safari` / `ios`) в мобильных профилях.** Базово ставь `firefox`, запасные варианты: `qq`, `edge`, `android`, `randomized`. Не переключай отпечаток «на лету» при заморозке: получишь штраф ~600 с.
- **Для мобильных профилей основной транспорт: VLESS + XHTTP + REALITY** (одно H2-соединение с мультиплексированием через xmux, мало хендшейков). RAW + Vision оставь как второй профиль для Wi-Fi. Vision несовместим с XHTTP и с Mux.Cool для TCP.
- **Не ставь точку входа для клиентов на ASN из списка «16-20»** (см. п. 2.1). Перед покупкой и после деплоя проверяй IP через `dpi-ch` или веб-чекер tcp-16-20 **с мобильного интернета каждого проблемного оператора** при выключенном VPN.
- **RU-релей одноразовый.** Российские хостеры обязаны удалять VPN по требованию РКН (Aeza — за 24 часа, VK Cloud банит ВМ, у Timeweb прокси запрещены в ToS), а Минцифры с 08.2026 продвигает мониторинг «белых» IP хостерами. Нужны автоматический передеплой (скрипт или IaC), запасной IP и ни одного секрета, который нельзя ротировать.
- **Раздельная маршрутизация обязательна**: `geosite:category-ru` и `geoip:ru` идут direct на клиенте; на Android российские приложения исключены из VPN (per-app bypass). Локальный SOCKS/HTTP-порт клиента либо выключен, либо закрыт логином и паролем.
- **Выход ≠ вход.** Желательно, чтобы трафик пользователей выходил в интернет с другого IP (второй IP, `sendThrough`, отдельный exit-сервер или WARP), чем тот, к которому подключаются клиенты.
- **SNI/target для REALITY**: не бери сайты за Cloudflare или другими общими CDN, Apple / Google / Microsoft / Amazon и вообще «заезженные» SNI. Лучше свой домен на своём IP (steal-oneself) или соседа по тому же ASN. Для whitelist-релея бери SNI из белого списка (см. исследование, раздел 5).
- **Каждое изменение конфига проверяй** командой `xray run -test -c config.json` до рестарта, а потом на матрице «оператор × профиль» (шаблон в исследовании, раздел 8).
- **Не коммить секреты**: UUID, privateKey, shortId, пароли панелей, токены хостеров. Конфиги в репозитории держи как шаблоны с плейсхолдерами.
- **Держи несколько профилей в подписке** (разные ASN, транспорты, fingerprint) и группу автопереключения (urltest / fallback) на клиенте. Держать всё на одном хостере нельзя.

## 4. Порядок диагностики «на LTE не работает»

1. Собери факты: оператор, регион, время, клиент и версия ядра, профиль (транспорт / fingerprint / SNI / ASN сервера), симптом.
2. Определи симптом по таблице (подробно в исследовании, раздел 2):
   - хендшейк проходит, потом загрузка висит → 16-20 → `dpi-ch` / tcp-16-20 checker → менять ASN или идти через релей;
   - какое-то время работает, потом всё замерзает на ~2 мин (особенно при открытии многих вкладок) → июньская схема → fingerprint `firefox` + XHTTP;
   - открываются только Госуслуги / Яндекс / VK, а 2ip.ru и 1.1.1.1 мертвы → белый список → релей с «белым» IP + «белый» SNI;
   - сервер недоступен (ping / SSH) из РФ часами → блок IP → менять IP;
   - мгновенный обрыв на хендшейке → SNI / fingerprint → менять SNI и fingerprint;
   - Windows + Билайн + TUN: деградация через 5–15 мин → режим системного прокси вместо TUN.
3. Меняй **один параметр за раз**, фиксируй результат в журнале.

## 5. Полезные инструменты

- `dpi-ch`: https://github.com/hyperion-cs/dpi-checkers (Linux / macOS / Windows / Android через Termux). Проверяет 16-20, «сибирские» ограничения, CIDR-вайтлист и DNS.
- Веб-чекер 16-20 для своего сервера: `https://hyperion-cs.github.io/dpi-checkers/ru/tcp-16-20/?host=<IP_или_домен>&provider=<имя>`.
- Белые списки (домены, IP, CIDR): https://github.com/hxehex/russia-mobile-internet-whitelist
- Проверка IP и доменов на блокировки РКН и CDN-подсети: cheburcheck.ru (есть API).
- `xray tls ping <домен>`: проверка кандидата в SNI/target (TLS 1.3, H2, X25519MLKEM768, размер сертификата).
- Форум ntc.party — это Discourse, у него есть JSON API: `https://ntc.party/t/<id>.json`, `https://ntc.party/search.json?q=...`. Номера ключевых тем перечислены в исследовании, раздел 10.
