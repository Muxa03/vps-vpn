# CLAUDE.md — инструкция для Claude по проекту vps-vpn

Этот файл Claude Code читает автоматически в начале каждой сессии. Здесь только сжатая выжимка.
Полное исследование с источниками (v2.1, 28.09.2026, по полным текстам тем ntc.party и Хабру): [`docs/research/2026-09-ntc-party-lte-vps.md`](docs/research/2026-09-ntc-party-lte-vps.md).

## 1. Контекст проекта

- Строим собственный VPN-сервис для пользователей из России.
- Основная связка: **VLESS + RAW(TCP) + REALITY** (Xray). На домашнем Wi-Fi работает, на мобильном интернете (LTE) бывают заминки, а у части операторов не работают релеи.
- Инфраструктура: несколько зарубежных VPS (в основном Германия и Нидерланды) и один VPS в России (используется как релей/каскад).

> **Заполни при первом запуске** (спроси у владельца и допиши сюда, без паролей и ключей):
> - список серверов: роль (entry / exit / relay), страна, хостер, **ASN**, IP-подсеть /24;
> - панель (3x-ui / Remnawave / Marzban / голый Xray) и **версия ядра Xray** на серверах и в клиентах;
> - клиентские приложения пользователей (v2rayNG, Happ, Streisand, v2RayTun, Hiddify, Karing…);
> - на каких операторах и в каких регионах проблемы (МТС / МегаФон / Билайн / T2 / Yota, регион), с датой.

## 2. Что ломает мобильный интернет в РФ (сентябрь 2026)

Механизмов несколько, и они действуют одновременно. **Сначала определи, какой сработал** (исследование, раздел 2), потом меняй что-то.

1. **«16 КБ» / TCP 16-20.** Соединения к IP хостингов из «чёрного» набора (Hetzner, OVH, DO, AWS, Oracle, Contabo, Scaleway, Vultr, Akamai, Gcore, BuyVM, Melbicom, CDN77, Cloudflare, Racknerd, Creanova, частично nuxt.cloud) замерзают после ~14–25 КБ. **Исключение — «белые» SNI** (~1000–2000 доменов, список на cheburcheck.ru). Для REALITY это значит: SNI и target — «белый» домен **того же ASN**. Свой домен (steal-oneself) на таком ASN не помогает. Блок гранулярный (по IP и подсетям), поэтому проверяй **конкретный IP**.
2. **Июньская / «сибирская» схема.** Подозрительная подсеть (в т.ч. **Selectel, Yandex Cloud, Cloud.ru**) + fingerprint chrome/safari/ios + больше 3 TLS-хендшейков за ~60 с → заморозка ~2 мин. При смене отпечатка во время заморозки — ~10 мин. VLESS+RAW+Vision (без мультиплекса) попадает под неё первым.
3. **Баны IP** (волны 04.08.2026 и 21.09.2026): полный дроп либо «хендшейк есть, после первого пакета данных тишина» (`REALITY: failed to read client hello`). 21–23.09 банили и простые REALITY на ≤10 клиентов, и selfsteal со своим доменом: маскировка от бана не страхует. Конфигом не лечится, помогает только новый IP; разбан занимает недели и месяцы, так что не жди его. **Забаненный IP недоступен и из российских ДЦ**, так что RU-релей до него не достучится. 21.09 местами банили подсетями, поэтому новый IP проверяй до переноса пользователей.
4. **Сканирование.** По наблюдениям участников форума, около 80% увиденных банов приходятся на REALITY «под google/apple/yahoo» и торчащие наружу порты (панель, подписки 2096, OpenVPN, SOCKS). Сканеры уровня Censys это видят. Сканер РКН — 212.192.156.0/22 (AS61280, UA `CyberOKInspect`); сканеры читают CT-логи и приходят через пару часов после выпуска сертификата.
5. **Белые списки на мобильном.** МТС и T2 фильтруют только по IP (L3): пингуется — значит работает всё. **МегаФон дополнительно фильтрует SNI.** UDP почти мёртв. «Белые» пулы облаков выбывают: Yandex Cloud 158.160.x и 84.201.x убраны в 05.2026, у T2 диапазонов YC в белом списке нет.
6. **Детект VPN приложениями** (с 15.04.2026): они узнают **выходной** IP и сдают его.
7. **Лимит соединений на IP хостера** (с 27.08.2026): Alexhost, netcup, HostHatch, MEVSPACE, LWLcom, ROUTE 95, Private Layer — третье TCP-соединение к IP без ответа. Под вход не брать.
8. **Триггерные блоки**: трафик самого абонента (UDP на DHT-адреса, «QUIC-подобные» пакеты, попытки открыть заблокированные сайты напрямую) вызывает блок на 10–15 мин. Всё не-российское — только через туннель.
9. **DNS** (с ~08.2026, не у всех провайдеров): DoT к 1.1.1.1/8.8.8.8 режется, DoH к `dns.google`/`cloudflare-dns.com` — по SNI, UDP/53 к ним подменяется резолвером НСДИ. Клиент с таким DNS в direct «подключён, но сайты открываются через раз».

## 3. Правила работы (обязательные)

- **Fingerprint `firefox`** во всех профилях. Не `chrome`, `safari`, `ios`; в 07.2026 сбоили также `android` и `random`, а с 21.09.2026 Ростелеком режет `randomized`. Не переключай отпечатки каскадом при заморозке.
- **На серверах наружу только 443.** Панель на `127.0.0.1`, доступ через `ssh -L`. SSH только по ключам (без root и пароля) и закрыт фаерволом кроме своих подсетей или port knocking; держи запасной доступ (консоль хостера), SSH из РФ к зарубежным VPS местами режут (указание ЦМУ ССОП 1705 о блокировке «уязвимых» портов, 09.2026). 3x-ui сам открывает порт подписок 2096 — закрой. Перед запуском проверь историю IP на Censys: IP с прошлым «REALITY под google» меняй сразу. Порты подписок, OpenVPN и SOCKS наружу не открывать. Перед REALITY ставь **SNI-фильтр** (dokodemo + routing по `serverNames` → остальное в blackhole). Входящие 443 из диапазонов своего хостера блокируй. Порты закрывай **до** запуска узла: Censys помнит увиденное. На выходах в routing: `geoip:private`, BitTorrent и порт 25 → block, иначе абузы и снос сервера хостером.
- **SNI/target REALITY:** никогда google, apple, yahoo, microsoft, amazon или сайты за Cloudflare/CDN. ASN в списке 16-20 → «белый» домен того же ASN, проверенный curl-тестом (исследование, 1.1). Чистый ASN → steal-oneself (свой домен и реальный сайт на этом же сервере). SNI мобильного белого списка (vk, ozon, max) — только на релее, который сам стоит в «белом» облаке; google/vk на IP не из их сетей — сигнал для DPI.
- **Транспорты:** для мобильных основной — **VLESS + XHTTP + REALITY, `mode: stream-one`, xmux задан явно на клиенте**: `maxConnections` 1–4, `maxConcurrency: 0` (они взаимоисключающие), остальные поля xmux тоже заполнены. С Xray v25.10.15 дефолт клиента `maxConcurrency = 1`, то есть мультиплекса нет. В v2rayNG xmux задаётся в поле «XHTTP Extra». На МегаФоне при БС `packet-up` и `stream-up` дают ~2 Мбит/с. Запасные: RAW + Vision (Wi-Fi) и gRPC + REALITY (против «сибирской»). UDP-протоколы (Hysteria2, AWG) — только резерв.
- **Порт 443 для REALITY.** Сам Xray v26.3.27 предупреждает: не-443 порт и target Apple/iCloud «очень легко приводят к блокировке IP». Исключение — запасной inbound на релее на случай шейпинга 443 (исследование, 1.5).
- **Вход ≠ выход.** Входная нода стоит на чистом ASN и только форвардит на выходную. **Выходную можно держать на Hetzner, OVH и подобных**: клиенты из РФ к ней напрямую не ходят. Для RU-релея exit обязан быть не забанен.
- **Выбор хостера:** не из списка 16-20, не «VPN-хостер» (Aeza, PQ/UFO, VDSina, h2.nexus, ishosting/inferno — нет) и не под лимитом соединений (Alexhost, netcup, HostHatch и др., п. 2.7). Кандидаты на тест (ревизия 28.09): **Hostkey (NL/DE)** и **Leaseweb NL**, **hostvds** — почасовой стенд; waicore понижен (блоки TCP и подсетей в 01 и 04.2026). Идеального хостера нет, лучше тот, у кого в ToS запрещены публичные VPN. Перед продлением тест конкретного IP с LTE нужных операторов. Во входном пуле 2–3 ASN.
- **RU-релей одноразовый:** «белые» IP выбывают, облака банят за прокси, VK Cloud не работает с физлицами. Держи 2 релея у разных хостеров и автоматический передеплой. Участок RU→EU делай через **reverse** (соединение инициирует зарубежный сервер) или IPIP. Самый простой релей без сплита — nginx `stream` + `ssl_preread`: проброс TLS по SNI на зарубежный вход без расшифровки (исследование, 5.6). Альтернатива для БС — XHTTP через российский CDN (стабильнее всех VK CDN), но только как резерв: CDN банят за VPN-трафик, а Минцифры с 31.08 требует выносить «белых» клиентов на отдельные IP.
- **Версия Xray:** на серверах стабильный релиз (v26.3.27) или явный `minClientVer` в `realitySettings`. Pre-release 26.7.x по умолчанию отшивает старых клиентов, а 3x-ui 3.5 сама его подтягивает. Не обновляй ядро вместе с панелью вслепую.
- **Клиенты:** российский трафик мимо VPN (per-app bypass или сплит); локальный SOCKS/HTTP только с паролем. Адрес сервера в профиле — IP. Удалённый DNS — через туннель (DoH), в direct — не DoH/DoT Google/Cloudflare (исследование, 1.7). Лучшая «гигиена» — российские приложения на отдельном устройстве или профиле.
- **Каждое изменение конфига:** `xray run -test -c config.json` → рестарт → матрица «оператор × профиль» (исследование, раздел 8). Меняй **один параметр за раз**.
- **Не коммить секреты** (UUID, privateKey, shortId, пароли, токены). В репозитории только шаблоны с плейсхолдерами.

## 4. Порядок диагностики «на LTE не работает»

1. Факты: оператор, регион, время, режим (обычный или БС), клиент и версия ядра, профиль (транспорт / режим / fp / SNI), ASN и IP сервера.
2. Симптом → механизм:
   - TCP-хендшейк есть, ClientHello ушёл, дальше тишина → **бан IP** → проверь через check-host.net и globalping.io с RU-нод → новый IP;
   - грузится и зависает на ~16 КБ → **16-20** → curl-тест SNI и dpi-ch → «белый» SNI того же ASN или другой ASN;
   - работает, потом всё замерзает на ~2 мин → **июньская схема** → `firefox`, XHTTP с `maxConnections: 1`, gRPC;
   - работают только VK, Яндекс и Госуслуги → **БС** → релей с «белым» IP (на МегаФоне ещё и «белый» SNI);
   - после обновления панели отвалились все → **версия Xray / `minClientVer`**;
   - на каскаде пинг и потери → `mtr --tcp -P 443` по участкам, `iperf3`, `tracepath`; исключи аварии;
   - Windows + Билайн + TUN → режим системного прокси;
   - «подключено», но сайты открываются через раз → **DNS** в профиле (исследование, 1.7);
   - XHTTP через CDN рвётся через несколько секунд загрузки → `packet-up` теряет запросы на границе CDN; CDN Yandex Cloud пускает только GET (исследование, 4.1);
   - через CDN `403` → CDNvideo (Selectel, Timeweb, Beget) ловит VPN: Xray ≥ 26.7.11 (слэш в пути), `vlessenc` вместо «голого» UUID, origin только по HTTPS (исследование, 4.1);
   - отвал на 10–15 мин без смены конфига → проверь триггерные блоки (исследование, 1.8).
3. Для RU-релея отдельно проверь по исследованию, раздел 5.5: IP в белом списке у оператора, SNI (МегаФон), fingerprint, не забанен ли exit, участок RU→EU.

## 5. Инструменты

- `dpi-ch`: https://github.com/hyperion-cs/dpi-checkers; DPI Detector: https://github.com/Runnin4ik/dpi-detector; веб-чекер 16-20: `https://hyperion-cs.github.io/dpi-checkers/ru/tcp-16-20/?host=<IP>`.
- «Белые» SNI для 16-20: https://cheburcheck.ru/whitelist/domains.csv, [SNI Tool](https://github.com/Erifirin/sni-tool), [RealiTLScanner](https://github.com/XTLS/RealiTLScanner) (домены в своей подсети).
- Мобильные белые списки: https://github.com/hxehex/russia-mobile-internet-whitelist (`cidrwhitelist.txt` — подсети, `ipwhitelist.txt` — отдельные IP; список общий для всех операторов и отстаёт). Проверка IP: `python3 scripts/check_whitelist_ip.py <IP>`; доля «белых» адресов у хостеров: `python3 scripts/whitelist_by_asn.py [ASN…]` (RIPEstat).
- Самопроверка «что видят сканеры»: https://platform.censys.io, [ByeByeVPN](https://github.com/pwnnex/ByeByeVPN), `nmap -p- -sS -sV --version-all -sC --script "ssl-cert,http-open-proxy,socks-open-proxy" -T4 -Pn <IP>`. Детект VPN «как у РКН»: [RKNHardering](https://github.com/xtclovver/RKNHardering).
- Доступность IP из РФ: check-host.net, globalping.io, динамические сканирования cheburcheck.ru (с 27.09.2026).
- `xray tls ping <домен>` — проверка кандидата в target.
- **Форум ntc.party** (Discourse, открытый JSON API без ключа). Если `ntc.party` недоступен, используй зеркало **`ntc.rkn.quest`** с теми же путями. Номера ключевых тем — в исследовании, раздел 9. Выгрузка: `scripts/ntc_dump.sh` (переменная `NTC_BASE`).
  - Поиск: `/search.json?q=<запрос>` → `topics[]` и `posts[]` (`topic_id`, `post_number`, `blurb`). Фильтры в `q`: `after:2026-06-01`, `before:`, `order:latest`, `in:title`, `#<slug>`.
  - Тема целиком в markdown: `/raw/<topic_id>?page=N` (по 100 постов; пустой ответ — конец). Отдельный пост: `/raw/<topic_id>/<post_number>`.
  - Метаданные: `/t/<topic_id>.json` (`posts_count`, `title`). Свежие темы: `/latest.json`.
  - Пауза ~1 с между запросами. У длинных тем читай последние страницы: там актуальное.
  - Зеркало `ntc.rkn.quest` — Cloudflare Worker с **общей суточной квотой** на всех посетителей. При её исчерпании отдаётся `429` с `error code: 1027` до сброса в 00:00 UTC; ретраи не помогают. Качай только нужное, для массовой выгрузки используй сам `ntc.party` (из РФ — через VPN).
- **Хабр** (второй источник, открытый JSON API): поиск `https://habr.com/kek/v2/articles/?query=<запрос>&order=date&fl=ru&hl=ru&page=N` → `publicationIds`, `publicationRefs[id].timePublished`; статья `/kek/v2/articles/<id>/?fl=ru&hl=ru` (`textHtml`); комментарии `/kek/v2/articles/<id>/comments/?fl=ru&hl=ru`. Поиск шумный: фильтруй по дате и заголовку, а в комментариях часто самое ценное (ValdikSS, 0ka и др.).
